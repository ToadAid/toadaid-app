## Goal

Open the first consequence-adjacent conversation cut: the receiver **prepares a delivery candidate** for an admitted D-P16 composition — a delivered copy of the record (D-P16 dv/kind verbatim, never re-stamped), a receiver-recorded destination audience tied to the record's own addressed agent within the declared vocabulary, and a receiver-recorded delivery-intent event with its own freshness basis — assessed by one frozen ceremony (`assessPondDeliveryCandidateDecision`) over the delivered record's full re-run admission, the D-P15 read gate, and the establishment echoes. The prepared state is `delivery_candidate_prepared_session_scoped_no_dispatch`: transport, dispatch, receipts, consequences, acceptance, grants, and authority all stay refused (their own later lanes). Refused preparations store nothing.

## Load-bearing mechanism

- **A delivered copy can only carry a candidate if it is currently admitted.** The decision re-runs the frozen D-P16 record admission over the delivered copy with the same re-timed legs (design-B per-assessment re-timing — the D-P15 reassessment and D-P16 surface precedent); a stale, out-of-scope, invalid, or re-stamped delivered copy refuses at `delivered_record_not_currently_admitted` with the mapped re-run reason honest. A re-stamp tamper (the delivered copy carrying the D-P17 dv) refuses as `conversation_record_invalid` — candidate validity deliberately does NOT pin the delivered copy's dv; the re-run does.
- **Intent freshness leads the ladder.** `delivery_intent_not_session_current` fires on the intent's own D-P2-style diagnosis (metadata → evaluation time → maximum age → future time, fresh boundary inclusive) BEFORE the gate — the ladder-order isolation of the intent-expiry refusal. Recorded deviation: because the intent event is the newest event in the chain, under one shared declared maximum age no arm can show intent-stale-while-gate-fresh (intent staleness implies every older event is staler); the isolation is by ladder order, and the arm's mapped leg echoes stay honestly stale alongside.
- **Session-scope binding.** The intent must postdate both the establishment event and the delivered composition (`recorded_at ≥ established_at` AND `recorded_at ≥ composed_at`): an intent recorded before the composition it would deliver is not in the session's scope, refusing `delivery_intent_not_of_the_current_session_scope` even when its own freshness is green.
- **Two separate destination checks (the D-P16 dedicated-cause pattern).** `delivery_destination_not_declared` (dedicated cause, satisfied list empty) fires when the destination ref is outside the declared vocabulary — an audience is never inferred (scope-sov L54-60); a declared destination that does not tie the delivered record's own addressed agent folds into `receiver_delivery_candidate_proof_incomplete` with `delivery_destination_bound_to_delivered_record` unsatisfied and every leg echo green.
- **The delivered text never enters any assessment.** The delivered copies in the fixture carry the D-P16 text verbatim for realism, but the ceremony sees records and metadata only; the delivery module's verdict rows pair the composed texts to decisions by index from shell state, never from the assessment.
- **Cause ladder (8 reasons), echoes computed on every arm before cause selection.** `delivery_candidate_invalid` → `delivery_intent_not_session_current` → `live_session_read_gate_not_live_activated_refused_or_not_fresh` → `delivered_record_not_currently_admitted` → `delivery_intent_not_of_the_current_session_scope` → `delivery_destination_not_declared` (dedicated) → `receiver_delivery_candidate_proof_incomplete` (basis/postures/bound, with unsatisfied check names readable) → `all_delivery_candidate_checks_satisfied`.
- **The forbidden-key inventory widened once.** `POND_STAGE_DP17_FORBIDDEN_DELIVERY_KEYS` = the frozen D-P16 union plus four keys this lane exists to refuse: `dispatchedMessage`, `sentMessage`, `deliveryReceipt`, `agentTaskAcceptance` — exact-key deep walk on candidate and assessment. `agentReply`, `agentReplyComposition`, `deliveredMessage`, `replyComposition`, `chatMessage`, and `conversation` stay forbidden exact keys from the D-P16/D-P14 inventories.

## Recorded deviations from the implementation plan

1. **The intent-expiry isolation is by ladder order, not by arm arithmetic.** The plan asked for the intent-expiry arm to have "the gate legs re-timed fresh" while the intent expires; under one shared `receiverMaximumAgeMs` that combination does not exist — the intent event is the newest event in the chain, so when it is over the age, every older event (establishment, composition, read gate) is staler. The implemented arm fires `delivery_intent_not_session_current` first in the ladder and carries honestly stale leg echoes; the gate-expiry arm carries the honest contrast (the gate refuses while the intent and the delivered record's own freshness diagnoses stay fresh — 60_001 vs 39_001/59_001). No separate maximum age for the intent was invented (that would be a new policy field with no law basis; the shared D-P2 age stays).
2. **The retracted arm's evaluation instant.** The plan carried the D-P16 retraction pair (1_800_000_070_000 / 1_800_000_075_000) for the confined arm; evaluation at 75_000 would make the intent event (81_000) future-time refused for a confusing second reason. The confined arm evaluates at 1_800_000_082_000 (after the intent event), so the retraction is the isolated, honestly-echoed cause.
3. **The future-intent arm is a candidate-only variation.** The fixture emission is keyed on the evaluation-instant NAME (`receiverEvaluatedAtEpochMs` always emits the shared pin), so an evaluation-instant override is unrepresentable in emission (an override would compute one assessment over a different pair than the emitted pin). The future arm instead pins the intent event 100 ms beyond the lane evaluation instant (1_800_000_090_100), keeping the pair shared and the semantics identical; the generator now refuses such an override loudly.
4. **The shell-drive timeline stays inside the shared freshness horizon.** The D-P6 observed event is pinned at 1_800_000_030_000, so the legs' freshness window closes at 1_800_000_090_000; the plan's drive pair (recorded at composition + 20s = 81s, prepared at 91s) would stale the observation leg. The drive reuses the D-P16 drive's 65_000 horizon: intent recorded at composition + 500ms (61.5s), preparation evaluated at 62.0s, retraction/confinement at 64s/65s — the fixture-clock arms still prove the 60-second clock honestly through their own pinned instants.
5. **`agentReply`/`chatMessage` widen probes kept** in both the fixture inventory slice and the selftest widen set over the plan's list — the wider inventory (D-P16 base) already forbids them, and the probes prove it stays forbidden here too.
