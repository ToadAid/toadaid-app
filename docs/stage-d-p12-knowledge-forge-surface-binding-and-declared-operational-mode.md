## Proof model

- **Exact provenance pinning, not regex-only.** Unlike D-P1's 40-hex regex validation, contract 1's frozen commitment table (`POND_STAGE_DP12_FORGE_SURFACE_COMMITMENTS`) pins each surface's exact forge commit, forge tree, companion repository, and companion commit — the identity check compares field-by-field against the table, so a single flipped hex character (e.g. p5d `d4cf…a8ee` → `d4cf…a8e0`) refuses `exact_forge_source_identity_per_surface` while the record stays well-formed. The per-surface `surfaceKind` is pinned to the same table.
- **The binding and the ui cannot drift.** The selftest re-extracts the surface ids, commits, trees, companion repositories/commits, posture literals, lifecycle literals, and the law anchor straight from the four `ui/pond-knowledge-forge*.js` module texts and asserts equality with both the fixture record and the contract's frozen table. The ui files carry no D-P12 vocabulary — the binding is receiver-owned vocabulary about the ui, never ui vocabulary.
- **Normalized authority posture.** The four ui posture objects (p5b `knowledgeAuthority`/`instructionAuthority`, p5c/p5d/p5e `authority`, p5e `lifecycleAuthority`) carry a common five-literal intersection — `KNOWLEDGE_ONLY` / `NONE` / `NOT_INCLUDED` / `NONE` / `NOT_INCLUDED` — which the contract normalizes to `PondKnowledgeForgeSurfaceAuthorityPosture`; the p5e lifecycle set (`EXTERNAL_REQUIRED_NOT_ESTABLISHED`, persistence `NONE`, `executable: false`) travels as a separate top-level field. No ui text changes; the mapping is proven in selftest block 2.
- **Declared mode: basis is vocabulary, never inference.** The basis vocabulary is exactly six literals: the satisfiable `receiver_recorded_explicit_declared_profile` and five valid-but-unsatisfied refused bases — `inferred_from_purpose`, `inferred_from_operator_prompt`, `inferred_from_forge_surface_provenance`, `model_self_selected`, `derived_from_skill_library_state` — each refused arm carrying its exact literal in `refusedDeclarationBasis`. A profile outside TRADING/HELPER/BUILDER refuses `declared_profile_out_of_vocabulary` with `declaredProfile: "not_recorded"` — there is no fourth literal, ever.
- **One agent, one profile.** The record binds an `agent:`-prefixed agent ref (the fixture pins `agent:fixture:stage-d-p0:trading-desk-agent0`); the composition requires the declaration to name the receiver-held agent ref, not just any agent's record — the D-P10 held-principal binding restated for the agent side.
- **Mandatory stricter-lane refusal posture.** Every record carries `stricterLaneRefusalPosture` with `laneAdmissionEstablished: false` and the five refused literals (`walletOrSigningAuthorityRefused`, `tradingExecutionRefused`, `credentialUseRefused`, `deploymentOrDestructiveMutationRefused`, `publicPublishingOrSocialPostingRefused` — agent-identity L153).
