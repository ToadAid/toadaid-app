## Goal

Prove Pond's frontend is agent-implementation-neutral: one exact-shape projection contract (`assessPondGenericAgentFrontFace`, `src/contracts/pond-generic-agent-front-face.ts`), one native keyboard-operable selector, and three deliberately heterogeneous agents passing through it — the specialist `toadaid.agent0` (`fixture_available`, installation projected), the personal `toadaid.agent1` (`fixture_disconnected`), and the non-ToadAid remote external `agent:community:sample-generic` (`fixture_discovered`, `admissionState: "unknown"`, no installation, only a generic capability ref). Selection changes presentation and nothing else; the D-P16 conversation lane stays untouched.

## Load-bearing mechanism

- **Exact-shape, fail-closed seam input.** A projection is valid only with the exact 16-key shape, the contractVersion and kind literals, vocabulary membership for `profile` (5 values) / `connectionState` (7 labels) / `admissionState` (4 values), `projectionSourceKind: "in_memory_fixture_only"`, bounded strings, `installationId: string | null`, distinct bounded capability refs, and the pinned posture literals. Duplicate `agentId`s, an unknown selection (`selected_agent_not_found`), extra or planted keys (a planted `credential` refuses), an empty capability string, malformed or unbounded input, or a projections array outside 1–32 entries re-fuse at `generic_agent_projection_input_invalid` — and every refusal echoes NOTHING (`selectedAgent: null`, empty extensions): an unknown or malformed agent is never represented.
- **Vocabulary-only connection states.** All seven fixture labels (`fixture_disconnected | fixture_discovered | fixture_not_admitted | fixture_available | fixture_busy | fixture_unavailable | fixture_failed`) are structurally accepted and presented, and the effect ceiling is identical on every label: a projected `fixture_available` label is presentation availability, not availability, `fixture_not_admitted` is a label, not an admission finding, and no label opens, advertises, or probes anything.
- **Two extension cards driven by declared refs only.** Base Chat always presents `preview_available_no_transport` (a target preview — no message composition or delivery); Knowledge Forge presents `declared_but_withheld_no_activation` exactly when the selected agent's projection declares `toadaid.addon.knowledge-forge`, else `not_declared` — withholding is the visible posture, and no add-on activation path exists anywhere in the cut.
- **The all-false ceiling as type and runtime both.** `PondStageDP25FrontFaceAssessment` carries the 9-key ceiling (`agentIdentityAcceptedAsAdmission`, `projectedAdmissionAcceptedAsAdmissionDecision`, `declaredCapabilityAcceptedAsGrant`, `connectionOpened`, `credentialStoredOrProjected`, `messageComposedOrDelivered`, `agentInvoked`, `addonActivated`, `currentTruthEstablished`), compile-time pinned all-false by `PondStageDP25Invariant_AllEffectCeilingsFalse` and `PondStageDP25Invariant_ActivationAndAuthorityRemainAbsent` (`runtimeActivationPosture: "not_included"`, `authority: "none"`), with `selectionChangesPresentationOnly: true` re-asserted by the selftest on every arm including the refusal arms.
- **Deterministic render ceremony (the established esbuild shape).** `scripts/render-stage-d-generic-agent-front-face.mjs` bundles the record module with an stdin entry re-exporting the real assessor — esbuild 0.28.2, ESM, `platform: "browser"`, `target: ["es2022"]`, unminified with `keepNames`, no timestamp, per-line trailing whitespace stripped, `--check` byte parity mode — producing the committed `ui/generated/pond-stage-d-generic-agent-front-face.js` + provenance JSON (`renderedStages: ["D-P25"]`, inputs naming the contract + fixture, the record module named in `record`). The selftest drives the SAME assessor from the generated bundle (generated parity wire) and asserts the generated record carries no transport primitive (`assessSelection`, `connect`, `send`, `deliver`, `invoke`, `admit`, `activateAddon` all absent).
- **Fill-once, inspection-first renderer.** `ui/pond-generic-agent-front-face.js` renders strictly over the committed record: version tie (`data-generic-agent-record-version === contractVersion`), the record's `runtimeActivationPosture`/`authority` literals pinned, textContent-only output, a native `<select>` (keyboard-operable native `change` event), polite atomic status, visible focus (44px control), fail-closed marking (`data-generic-agent-render-posture="fail_closed"`, selector disabled, children withheld) on any missing node, wrong record version, posture mismatch, or out-of-set selection, and no `fetch(`, `WebSocket`, `localStorage`, or `sessionStorage` anywhere in the module.
